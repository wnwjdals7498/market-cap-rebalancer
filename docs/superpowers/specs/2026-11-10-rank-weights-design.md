# 시총 1~5위 비율 전략 설계

작성 2026-11-10. 대상 저장소 `market-cap-rebalancer` (main `5782707` 기준).

## 1. 의도

지금 전략은 시장별 시총 1위 한 종목을 들고(SOLO), 1위가 바뀌면 1·2위 반반(SPLIT)으로 옮긴다. 사용자는 한 종목 쏠림 대신 상위 5종목에 정해 둔 비율로 나눠 담고, 그 비율·속도·국가 배분을 웹 설정 화면에서 직접 조정하고 싶어 한다. 변화는 하루에 정해 둔 양만큼만 일어나야 한다.

## 2. 사용자가 정한 것

1. **후보 종목.** 시장별 주식 5 + 단기채 ETF 1 + 장기채 ETF 1 = 7종목, 미국·한국 합쳐 14종목.
2. **순위 비율.** 매일 시장별 주식 5종목을 시총 순으로 줄 세우고, 주식 몫 안에서 1~5위에 설정한 비율(합 100)을 준다. 미국과 한국은 같은 비율표를 쓴다.
3. **기존 방식 대체.** SOLO/SPLIT 은 없어진다. 비율표 100/0/0/0/0 이 지금의 1위 단독에 해당한다.
4. **순위 변경 대기일.** 설정 항목이다. 새 순위가 이 일수만큼 연속 유지돼야 목표 비율에 반영한다. 운용 값은 0 (당일 반영).
5. **하루 최대 이동량.** 포켓(시장별 계좌 몫) 자산 대비 %. 순위 비율 조정, 주식/채권 비중 조정, 단기/장기채 조정 등 모든 조정에 적용한다. 목표와의 차이가 크면 하루에 이만큼만 옮기고 나머지는 다음 날 이어서 옮긴다.
6. **미국/한국 비율.** 설정한 `us_pct` 를 실운용에서 맞춘다. 환전은 자동으로 하지 않는다(A안): 하루 최대 이동량 안에서 환전할 금액을 계산해 텔레그램으로 안내하고, 사용자가 직접 환전한다.
7. **배포 값.** 1~5위 비율 50/30/20/0/0, 주식/채권 60/40 (`stock_pct` 60), 채권 안 단기/장기 100/0 (`short_bond_pct` 100), 한국/미국 40/60 (`us_pct` 60), 순위 변경 대기일 0. 하루 최대 이동량은 지금 값(`step_pct` 10) 유지.
8. **환전 현금 마련(나안).** 5절 환전 흐름대로 미리 팔고, `fx_wait_days` 안에 환전이 없으면 재투자 후 환전 계획을 멈춘다.
9. **한국 후보.** 실제 시총 상위 5 (5절 기본 후보 종목).

배포 첫날 예상 [추론, 전제: 2026-11-10 `equity` 기록 미국 $90.6k · 한국 0, 2026-11-09 한국 포켓 현금 0]: 미국 비중 약 100% 로 목표 60% 보다 크므로 환전 계획이 생긴다. 미국 포켓에서 하루 최대 이동량(포켓의 10%, 약 $9k)만큼 팔아 현금을 만들고 달러→원화 환전을 안내한다. 모의계좌에서 환전이 안 되면 3일 뒤 재투자하고 환전 계획이 꺼진다.

## 3. 목표 / 비목표 / 하지 말아야 할 것

**목표**
- 위 2절이 백테스트와 실운용에서 같은 규칙(`strategy.py`)으로 동작한다.
- 새 설정 전부를 웹 설정 화면(`/app/`)과 CLI(`jobs.py config`)에서 바꿀 수 있고, `settings_log` 에 이력이 남고, 다음 tick 부터 적용된다.

**비목표**
- 자동 환전. KIS Open API 에 환전 주문 API 가 없다 [검증: `koreainvestment/open-trading-api` 커밋 `3a9be59` (2026-10-28) 의 API 목록 `MCP/KIS Code Assistant MCP/data.csv` 334건에 환전 API 없음]. 통합증거금 자동 경로도 이번 범위 밖.

- 실계좌 주문 활성화. 기본 DRY_RUN → 모의 `--submit` 순서는 그대로.
- 모바일 앱.

**하지 말아야 할 것 (이렇게 되면 동작해도 실패)**
- 하루 최대 이동량을 넘는 매매가 나간다 (단, 5절 "첫 투자" 예외).
- 전략 관리 종목(후보·채권·정리 대상 목록) 밖의 종목을 사고판다. 판정은 지금 `managed()` 처럼 종목 단위다.
- 백테스트와 실운용 규칙이 갈라진다.
- 데이터 검증(오래된 시세 40분, 주식수 ±20%, 시총 ±40%)이 완화된다.
- `runs` 테이블의 1세션 1회 실행 보장이 우회된다.
- 환전 안내가 매일 같은 내용으로 쏟아지거나, 안내 금액을 실제로 마련해 두지 않은 채 안내한다.

## 4. 제약

- `AGENTS.md` 규칙: 전략 규칙은 `strategy.py` 에만. 백테스트 재실행 → `results/summary.md` 갱신 → README 규칙 표 갱신을 규칙 변경과 같은 커밋에. 전략 수치는 `Config` 필드. 시각은 `exchange_calendars` 로만. 구현 단계 하나 = 커밋 하나, 커밋 전 pytest.
- 설정 변경은 `control.py` 경유(검증, `settings_log`, 텔레그램 1회 알림). API 를 바꾸면 `scripts/export_openapi.py` + `npm run gen:api` 로 `frontend/openapi.json`, `schema.d.ts` 갱신.
- 운영 중인 서버(`mcr-tick.timer` 5분 주기, broker=kis DRY_RUN)에 반영하므로 `mcr.db` 의 기존 기록(runs, orders, equity, settings)은 그대로 두고 읽혀야 한다. 기존 `LeaderState` 저장값은 새 상태로 대체해도 된다(대기일 0 이라 이어받을 기억이 없다).
- KIS 모의투자 계좌에서 사용자가 직접 환전할 수 있는지는 확인되지 않았다. 안 되면 모의 단계에서는 환전 안내를 따를 수 없다 — 기능은 그대로 만들고 안내만 쌓인다.

## 5. 내가 정한 것 (사용자 확인 전)

- **설정 필드.**
  - `rank_weights`: 5개 수 (각 0~100, 합 100). 코드 기본값 = 사용자 배포 값 50/30/20/0/0. `stock_pct` 60, `short_bond_pct` 100, `us_pct` 60 도 코드 기본값을 배포 값과 같게 둔다.
  - `confirm_days`: 의미를 "순위 변경 대기일"로 바꾸고 기본 0. 범위 0~30 유지.
  - `step_pct`: 의미를 "하루 최대 이동량(포켓 대비 %)"으로 넓힌다. 기본 10, 범위 1~100 유지.
  - `short_bond_pct`: 채권 몫 중 단기채 비율(%), 나머지는 장기채.
  - `fx_band_pp`: 미국 비중이 `us_pct` 에서 이만큼(%p) 넘게 벗어나야 환전 안내. 기본 5. 환전 스프레드(0.25% 편도) 때문에 작은 차이마다 환전하지 않기 위함.
  - `us_universe`, `kr_universe`: 각 주식 5종목. `us_short_bond`, `us_long_bond`, `kr_short_bond`, `kr_long_bond`: 채권 ETF.
  - 삭제: `pair_confirm_days`, `solo_after_days`, `us_bond`, `kr_bond`, `fx_mode`(실운용은 항상 `us_pct` 를 맞춘다; 백테스트도 같은 규칙).
- **대기일 규칙.** 확정 순위(confirmed)와 후보 순위(pending, 연속 일수)를 상태로 저장한다. 오늘 순위가 확정 순위와 다르면, pending 과 같을 때 연속 일수 +1, 다르면 pending 을 오늘 순위로 바꾸고 1. 연속 일수 ≥ `confirm_days` 이면 확정. `confirm_days` = 0 이면 매일 오늘 순위가 곧 확정 순위.
- **하루 최대 이동량 계산.** 포켓의 현재 보유 → 전체 목표(순위 비율 × 주식 몫, 단기/장기 × 채권 몫)로 가는 차이를 하나의 비율 α 로 줄인다. α 는 하루 매도 합계(줄어드는 쪽 합계)가 `step_pct`% × 포켓 자산을 넘지 않게 정한다. 지금 `plan_targets` 가 주식 몫에만 거는 상한을 포켓 전체로 넓힌 것이다. `min_trade_pct` 생략 규칙은 그대로.
- **첫 투자 예외.** 포켓에 전략 보유가 하나도 없을 때(현금만 있을 때)의 첫 매수는 상한 없이 한 번에 한다 — 지금 동작 유지. 그 뒤 들어오는 현금(환전 입금 포함)은 상한을 따른다.
- **후보 변경.** 웹·CLI 에서 후보와 채권 종목을 바꿀 수 있다. 저장 시 형식 검증: 한국 `^\d{6}\.KS$`, 미국 `^[A-Z][A-Z.\-]{0,5}$`, 시장별 주식 5개 중복 없음, 채권 2개는 주식과 겹치지 않음. 후보에서 빠진 종목은 "정리 대상" 목록에 남겨 목표 0 으로 하루 이동량 안에서 팔고, 수량이 0 이 되면 목록에서 지운다.
- **전략 관리 범위는 종목 단위.** 후보·채권·정리 대상 목록에 든 종목은 계좌 수량 전부가 전략 몫이다(지금 `managed()` 와 같음). 목록 밖 종목은 건드리지 않는다. 이 계좌는 전략 전용으로 본다 — 개인 보유 종목을 후보에 넣으면 그 수량도 전략이 조정한다.
- **배포 첫날 이관.** 한 번만 도는 이관 단계를 둔다. `settings_log` 출처는 `migration`.
  - `confirm_days` 를 0 으로(사용자가 정한 운용 값). 저장된 옛 값 3 은 SPLIT 전환 일수라 의미가 다르다.
  - 저장 설정에서 없어진 키(`pair_confirm_days`, `solo_after_days`, `us_bond`, `kr_bond`, `fx_mode`)를 지운다. `load_config` 가 `Config(**saved)` 라 남아 있으면 실패한다.
  - 옛 후보·옛 채권 중 새 목록에 없는 종목을 정리 대상에 넣는다. 예: 미국 모의계좌의 IEF(2026-11-09 기록 약 $39.3k, 포켓의 약 43%)는 하루 이동량 안에서 팔리고 SHY/TLT 로 옮겨진다.
  - 옛 `LeaderState` 는 버린다.
- **환전 알림 방식.** 환전 계획이 있는 동안 일일 보고에 한 줄로 매일 넣는다. 텔레그램 별도 알림은 계획이 새로 생기거나 금액·방향이 바뀌거나 해소될 때만 보낸다. 같은 별도 알림을 매일 반복하지 않는다.
- **환전 안내 흐름.**
  1. 일일 보고(08:00 KST, `REPORT_AT`) 때 총자산(원화 환산)에서 미국 비중을 계산한다. `|미국 비중 − us_pct| > fx_band_pp` 이면 "환전 계획"(방향, 금액)을 저장한다. 금액 = min(목표까지 차이, 넘치는 쪽 포켓 자산 × `step_pct`%).
  2. 넘치는 쪽 포켓의 다음 signal 은 투자 가능액에서 계획 금액을 빼서 그만큼 현금을 확보한다(하루 이동량 안).
  3. 다음 일일 보고에서 확보된 현금만큼 "미국 포켓 현금 $X 를 원화로 환전" (또는 반대) 안내를 보낸다. 안내는 하루 1회.
  4. 사용자가 환전하면 받는 쪽 포켓 현금이 늘고, 그 포켓의 다음 signal 이 목표 비율대로 매수한다(하루 이동량 안).
  5. 환전하지 않으면 확보한 현금은 그대로 두고 추가 매도는 하지 않는다. 현금 확보 후 `fx_wait_days`(기본 3일) 안에 환전이 없으면 [사용자 결정: 나안] 그 현금을 다시 투자하고(하루 이동량 안), `fx_enabled` 를 끈 뒤 텔레그램으로 알린다. 다시 켤 때까지 환전 계획을 만들지 않는다 — 팔고 다시 사는 반복을 막는다. 차이가 `fx_band_pp` 안으로 돌아오면 계획을 지운다.
  - 설정 추가: `fx_enabled`(기본 켜짐), `fx_wait_days`(기본 3, 범위 1~30).
- **백테스트의 환전.** 안내 다음 날 사용자가 환전했다고 보고 내부에서 처리한다(스프레드 `fx_spread` 적용). 시나리오 표는 새 전략 기준으로 다시 짠다: 설정값, 비율표 100/0/0/0/0(1위 단독), 대기일 3, 이동량 100%(즉시), 지수 60/40 비교, 단순보유 비교.
- **기본 후보 종목.** 확인 근거: yfinance `fast_info.marketCap`, 가격 이력 시작일 (2026-11-10 조회).
  - 미국 주식: AAPL 5.10T, NVDA 4.31T, MSFT 4.05T, GOOGL 3.54T, AMZN 2.89T (달러). 모두 지금 후보 8종목 안의 상위 5.
  - 한국 주식 [사용자 결정: 실제 상위 5]: 005930 1,237조, 000660 801조, 402340(SK스퀘어) 95조, 373220 74조, 005380 71조 (원). 지금 후보의 207940 은 70조로 6위라 빠지고 이관 때 정리 대상이 된다.
  - 채권: 미국 단기 SHY (1-3년, 2002-07 상장), 장기 TLT (20년+, 2002-07). 한국 단기 114260 KODEX 국고채3년 (2009-07), 장기 385560 KBSTAR KIS국고채30년Enhanced (2021-05-26, 백테스트 시작 2021-10-26 이전). 153130·157450 은 현금성(KRW Cash, Money Market)이라 단기채에서 제외.

## 6. 빌더에게 맡기는 것

- 구현 시점에 5절 후보·채권 종목의 시세·주식수가 실제 소스(KIS, yfinance)에서 조회되는지 확인(근거를 커밋 본문에).
- 상태(확정/후보 순위, 환전 계획, 정리 대상)를 저장하는 테이블·키 이름과 형식.
- 함수 분해와 이름, 기존 `LeaderState`/`update_state`/`plan_targets` 를 고칠지 새로 둘지.
- 웹 화면 배치(비율표 입력 5칸과 합계 표시, 후보 종목 편집, 상태 화면의 순위·환전 안내 표시).
- 단계 나누기(전략 → 실운용/환전 → 설정/API → 화면 → 백테스트·문서 등)와 각 단계 테스트.
