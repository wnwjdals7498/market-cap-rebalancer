# 후보 풀 자동 갱신 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 시장별 후보를 고정 5종목에서 "매주 yfinance 검색으로 갱신하는 15종목 풀"로 바꾸고, 매일 그 풀의 검증된 시총 순위 상위 5에 `rank_weights` 를 적용한다.

**Architecture:** 새 모듈 `screener.py` 가 검색·걸러 내기를 맡는다. 풀은 기존 `us_universe`/`kr_universe` 설정을 그대로 쓰고, `jobs.run_signal` 이 주 1회 `control.update(..., "system")` 로 갱신한다(이력·알림·`retired` 재사용). 순위·비율·매매 로직은 그대로다.

**Tech Stack:** Python 3.12, yfinance 1.8.0 (`yf.screen`, `EquityQuery`), SQLite, React/TS.

**Spec:** `docs/superpowers/specs/2026-11-10-rank-weights-design.md` 7절 (앞 절 전부 유효).

## Global Constraints

- 브랜치 `feat/top5-pool`(worktree `.worktrees/pool`), main 에는 끝난 뒤 한 번 병합. 단계 하나 = 커밋 하나(커밋은 지시자가). 커밋 전 `.venv/bin/python -m pytest -q` 통과, 프런트 변경 시 lint/typecheck/test/build 0, `api.py` 변경 시 OpenAPI·`schema.d.ts` 재생성.
- 테스트는 네트워크 금지: 검색 함수는 주입(fake)으로 시험. `mcr.db`, `.env` 를 열거나 쓰지 않는다.
- 검증 상수(40분, ±20%, ±40%) 값은 바꾸지 않는다. HOLD 범위만 7절대로 좁힌다 — 커밋 본문에 이유를 쓴다(AGENTS.md).
- 설정 기본값: `pool_size=15`, `pool_auto=True`. 한국 풀은 `^\d{5}0\.KS$`(KOSPI 보통주). 미국 풀은 기존 패턴, ADR 포함.

## Review Focus

1. **검색 결과가 15개보다 적거나 실패** → 이전 풀 유지, 그 주 1회 알림, signal 은 정상 진행. → Task A `test_screen_top_filters_and_dedupes`, Task B `test_pool_refresh_failure_keeps_old_pool_and_alerts_once`.
2. **풀에서 빠진 보유 종목**(예: 상위 15 밖으로 밀린 종목) → `retired` 로 가서 상한 안에서 매도. → Task B `test_pool_refresh_retires_dropped_holding`.
3. **풀 하위 종목의 데이터 이상** → 하루 전체 HOLD 가 아니라 그 종목만 제외; 상위 5 관련이면 HOLD. → Task B `test_suspect_outside_top5_is_dropped_not_held`.
4. **같은 회사 여러 종류·우선주**(GOOGL/GOOG, BRK-A/BRK-B, 005935.KS) → 하나만/제외. → Task A.
5. **수동 편집 후 자동 갱신**(`pool_auto` 켜짐) → 다음 주 갱신이 덮어씀; 끄면 유지. → Task B `test_pool_auto_off_keeps_manual_list`.

### Task A: 검색 모듈과 설정

**Files:** Create `screener.py`, `tests/test_screener.py`; Modify `strategy.py`(Config), `control.py`(LIMITS·검증), `tests/test_control.py`.

**Interfaces:**
- Produces:
  - `screener.screen_top(market: str, size: int, fetch: Callable[[str, int], list[dict]] | None = None) -> list[str]`: `fetch(region, count)` 기본은 `yf.screen(EquityQuery('eq', ['region', region]), sortField='intradaymarketcap', sortAsc=False, size=count)['quotes']`(region us/kr). `count = size * 3`(최대 250). 걸러 내기: `quoteType == "EQUITY"`; KR 은 `symbol` 이 `^\d{5}0\.KS$`; 같은 `longName` 은 `regularMarketPrice` 가 낮은 것 하나; `marketCap` 내림차순 상위 `size`. 결과가 `size` 미만이면 `ScreenError(RuntimeError)` 를 던진다.
  - `Config.pool_size: int = 15`, `Config.pool_auto: bool = True`. `us_universe`/`kr_universe` 기본값 = 구현일 `screen_top("US", 15)`, `screen_top("KR", 15)` 실제 결과(커밋 본문에 조회 시각과 목록).
  - `control.LIMITS`: `pool_size`(int 5~30, 라벨 "후보 풀 크기"), `pool_auto`(bool, "후보 풀 매주 자동 갱신"), `us_universe`/`kr_universe` 는 `"min": 5, "max": 30`(목록 길이), 라벨 "미국/한국 후보 풀 (자동 갱신)". 한국 목록 패턴은 보통주 `^\d{5}0\.KS$`(채권 필드는 기존 패턴 유지).
- [ ] 테스트: `test_screen_top_filters_and_dedupes`(fake quotes: GOOGL/GOOG 같은 longName → 낮은 가격 하나, `005935.KS` 제외, `ETF` 제외, `.KQ` 제외, 정렬·자르기, 부족 시 ScreenError), `test_pool_list_length_validation`(4개·31개 거부, 15개 허용, 한국 `005935.KS` 거부).
- [ ] 구현 → pytest 통과. 커밋 `Add a weekly market-cap screener for the candidate pool`.

### Task B: 주간 풀 갱신과 HOLD 범위 (jobs.py)

**Files:** Modify `jobs.py`; Test `tests/test_jobs.py`.

**Interfaces:**
- Consumes: Task A `screen_top`, `ScreenError`, `pool_size`, `pool_auto`.
- Produces:
  - `jobs.refresh_pool(conn, mkt: Market, session: str, cfg: Config, screen=screener.screen_top) -> Config`: `pool_auto` 이고 `pool:refreshed[mkt.code]` 가 `session` 과 같은 ISO 주가 아니면 `screen(mkt.code, cfg.pool_size)` → 목록이 바뀌었으면 `control.update(conn, {"config": {f"{code.lower()}_universe": new}}, "system")`, `pool:refreshed` 기록, `control.load_config` 로 새 Config 반환. `ScreenError`/예외 → 이전 Config 반환, `pool:failed[code]` 가 이번 ISO 주가 아니면 알림 1회 후 기록.
  - `run_signal(..., screen=screener.screen_top)`: 시작에서 `cfg = refresh_pool(...)`. `tick` 은 기본값 사용.
  - HOLD 범위: 의심 종목 `S` 에 대해 `S ∩ prev_confirmed[:5]` 가 있거나, 의심 값을 포함해 정렬한 오늘 순위 상위 5 에 `S` 가 있으면 HOLD(기존 동작). 아니면 `S` 를 오늘 순위에서 빼고 OK. 깨끗한 종목이 2개 미만이면 기존처럼 HOLD/오류.
- [ ] 테스트: `test_weekly_pool_refresh_once_per_week`(같은 주 두 번째 signal 은 screen 호출 없음), `test_pool_refresh_failure_keeps_old_pool_and_alerts_once`, `test_pool_refresh_retires_dropped_holding`, `test_pool_auto_off_keeps_manual_list`, `test_suspect_outside_top5_is_dropped_not_held`, `test_suspect_in_top5_still_holds`.
- [ ] 구현 → pytest 통과. 커밋 `Refresh the candidate pool weekly and scope HOLD to the top five`.
